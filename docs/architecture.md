# アーキテクチャ

## 構成

- **Postgres**: 状態管理（タスクの状態、取り込み済みデータ、キューなど）
- **サービス層**: 業務ロジックと権限チェックの置き場。権限は API 側で強制する
- **MCP サーバー**: エージェント向けの主窓口（サービス層のファサード）
- **Web ダッシュボード**: 人間向け。会議で両者のタスク進捗を見る共用管理画面（共有タスクのみ表示）

公開 REST API は作らない。必要になったら、同じサービス層の上に後から足す。
MCP とダッシュボードは同一アプリの別フェースでよい。

## 配置と公開範囲

- 配置先: manatago の VPS（さくらインターネット）
- 公開範囲: テールネット内のみ。Tailscale Serve で `*.ts.net` の HTTPS 名で出す（ドメイン購入は不要）
- 公開 HTTPS が要るのは Webhook 受け口を使う場合のみで、その場合も受け口だけに限定する
- Postgres のポートは公開しない

## セキュリティ

- エージェントごとに、範囲を絞った失効可能な API キーを使う
- 取り込んだ内容（議事録、メール、Web ページなど）は「データ」として扱い、指示として解釈しない
- 管理画面のログインはパスキーを基本とする
- OS とコンテナイメージは自動更新を前提とする

## データの置き場

- 定義・仕様・実装: このリポジトリ（Git）
- 状態・実データ: デプロイ先の DB（Docker ボリューム）
- 各 SaaS（Slack、メール、Drive など）は入口としてのみ使い、保持は基盤側で行う
- 取り込みはイベント駆動（Webhook）を主とし、定期取得を安全網とする
